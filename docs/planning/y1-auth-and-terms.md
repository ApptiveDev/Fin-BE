# Y1 회원가입·로그인과 약관, 개인정보

> 원본: 노션 「Y1 회원가입/로그인 PRD」, 「정보 수집 관련 이슈 / 약관 동의 항목」 및 하위 Q&A 3건, 「FE/BE 지시사항 (약관 내용 기반 설계를 위해)」, 「입력 정보 저장 동의」

## 개요

금융 서비스 가입은 보통 5~7단계를 거치고, 본인인증 단계에서 이탈이 가장 많다. Y-Fin.은 본인인증, ID/PW 생성, 상세정보 입력을 빼고 **SNS 로그인만으로 가입**하게 한다. 추천에 필요한 정보는 추천 단계에서 사용자가 원할 때 받는다.

레퍼런스: 토스(가입 전 가치 노출), 핀다·뱅크샐러드(점진적 온보딩), 카카오뱅크(카카오 계정 기반 빠른 가입).

## 목표와 지표

- 본질: 서비스 진입부터 메인 도달까지의 허들을 낮춰 가입 전환율을 확보한다.
- 북극성: 가입 유저의 40% 이상이 가입 당일 추천 프로세스를 시작
- KPI: 회원가입 전환율 3% 이상, SNS 버튼 클릭부터 메인 진입까지 20초 이내, 로그인 페이지 3초 내 이탈 5% 미만
- 보조: SNS 채널별 유입 비중, 약관 단계 이탈률, 마케팅 수신 동의율

## 사용자 여정

| 단계 | 경험 | 액션 |
| --- | --- | --- |
| 랜딩 | 서비스 가치 파악 | "나에게 맞는 금융상품 찾기" 등 CTA 클릭 |
| 로그인 선택 | 복잡한 가입이 없음에 안도 | 카카오/구글 버튼 선택 |
| 약관 동의 | 신뢰할 수 있는 수집임을 인지 | 필수·선택 항목 체크 |
| 온보딩 완료 | 바로 서비스 탐색 | 별도 입력 없이 메인 이동 |

## 기능 요구사항

### SNS OAuth 2.0 로그인

- 카카오, 구글 연동. 최초 로그인 시 자동 가입, 재방문 시 로그인.
- 수집: 유저 식별값, 이메일, 이름/닉네임.

### 약관 동의

- 필수 약관만 최소로 두고, "전체 동의"로 뎁스를 줄인다.
- 선택 항목은 기본 해제 상태로 두고 혜택 문구로 유도한다.
- 필수 약관 미동의 시 가입 버튼 비활성 + 토스트 안내.
- 전문 보기는 항목 우측 `>` 클릭 시 모달. 끝까지 스크롤해야 확인 버튼이 활성화된다. 제4조(서비스 성격), 제5조(면책)는 굵게·브랜드 색으로 강조한다.

### 세션 유지

- JWT로 인증 상태를 유지하고, 브라우저를 닫았다 와도 다시 로그인하지 않게 한다.
- 로그아웃, 회원 탈퇴(데이터 파기)를 제공한다.

## 약관 목록

최종 수정일 26-08-06 기준.

| 약관 | 동의 시점 | 유형 |
| --- | --- | --- |
| 만 14세 이상입니다 | 회원가입 | 필수 |
| 서비스 이용약관 | 회원가입 | 필수 |
| 개인정보 수집·이용 | 회원가입 | 필수 |
| 마케팅 정보 수신 및 프로파일링 | 회원가입 | 선택 |
| 입력 정보 저장 동의 | 저장 동의 모달 | 선택 |

기능 정의서(Y1-6)에는 위치기반 서비스 이용 동의(선택)도 있다. 약관 전문은 DB 시드(`V2__insert_reference_data.sql`)에 들어 있다. 구현 쪽 약관 구성은 [기획과 구현 차이](../implementation/plan-vs-implementation.md)에 정리했다.

서비스 이용약관의 핵심은 제4조다. Y-Fin.은 입력 정보로 가입 요건 부합 여부를 계산하는 시뮬레이션과 공개 정보 기반 상품 안내, 기관 공식 페이지 아웃링크를 제공하며, 금융소비자보호법상 판매대리·중개업에 해당하지 않는다.

## 입력 정보 저장 동의

추천 정보 입력을 마치면 "입력하신 정보, 마이페이지에 저장할까요?" 모달로 저장 여부를 묻는다(Y3-3). 동의하지 않아도 결과는 정상 제공된다.

- 저장 목적: 다음 진단 시 자동 입력, 마이페이지 조회·수정
- 저장 항목 12개
  - 자격 진단 정보: 생년월일, 거주 지역, 현재 신분, 근속 기간·첫 직장 여부, 개인 연 소득, 가구원 수·가구 소득, 무주택·세대주 여부, 거래 이력
  - 진단 조건 정보: 월 납입 희망액, 저축 기간, 핵심 혜택 선호, 은행 거래 우대 선호
- 보유 기간: 탈퇴 또는 삭제 요청 시까지
- 거부 시: 입력값은 결과 산출 후 즉시 파기
- 철회: 마이페이지 > 개인정보에서 언제든 삭제

모달 재노출 규칙:

| 직전 상태 | 정보 입력 완료 시 |
| --- | --- |
| 저장 이력 없음 (첫 진단) | 모달 노출 |
| 이전에 "저장하고 결과 보기" | 모달 없이 값 자동 갱신 |
| 이전에 "저장 없이 결과 보기" | 모달 재노출 (매번 저장 기회를 다시 준다) |

"아니오"를 고르면 서버 저장 API를 호출하지 않고, 값은 클라이언트 상태에만 둔다. 거부 비율 같은 행동 로그는 개인 식별 정보 없이 남긴다.

## 개인정보 관련 결정 (Q&A 요약)

**본인인증 없이 수동 입력으로 정보를 받아도 되는가?** 된다. 법이 보는 것은 인증 여부가 아니라 수집 동의와 목적 외 사용 여부다. 다만 수동 입력은 부정확하고(기억 오류, 최신성), 금융사 페이지에서 정보를 다시 입력해야 한다는 한계가 있다. 대응으로 판단 근거를 텍스트로 보여주고, 실제 자격 기준(중위소득 구간)에 맞춘 구간형 입력을 쓴다. 본인인증은 가입 승인 예측 고도화, 금융사 제휴, 마이데이터 확장 시점에 단계적으로 도입한다(간편 가입, 저장 시 휴대폰 인증, 마이데이터 연동 시 인증서).

**수동 입력 정보를 마이페이지에 저장해도 되는가?** 된다. 가입 시 동의 범위에 "맞춤형 금융상품 추천 서비스 제공 및 데이터 보관"이 들어 있으면 추가 동의 없이 가능하고, 아니면 별도 동의가 필요하다. 이 결정에 따라 위의 "입력 정보 저장 동의"를 선택 동의로 따로 둔다. 저장된 값은 사용자가 직접 입력한 추정치임을 화면에 밝힌다.

**민감정보에 해당하는가?** 아니다. 소득, 직장, 무주택 여부, 우대금리 충족 여부는 개인신용정보(신용정보법), 생년월일·지역·병역은 일반 개인정보(개인정보보호법)다. 보험 추천으로 확장해 질병 이력을 받게 되면 그때는 민감정보 별도 동의가 필요하다.

## BE 지시사항 (기획 요청)

- 약관 텍스트 버전 관리(v1.0, v1.1 등)
- 동의 시점의 약관 버전, 동의 시각, 접속 IP, User-Agent 기록
- 마케팅·위치기반 동의 여부를 마이페이지에서 바로 바꿀 수 있는 API
- 탈퇴 시 개인정보 즉시 파기(또는 법정 기간 후 자동 삭제)
- 소득 등 금융 정보는 암호화 저장, 로그인 정보와 분리 관리 권장
