# 서비스 개요

> 원본: 노션 「YFin 정본 팩트시트」, 「서비스 기획 피봇팅」, 「1차 설문조사 분석 리포트」 (2026-08 기준)

## 한 줄 정의

**Y-Fin.**(와이핀, Youth · Finance · Finish)은 금융 초보 청년(만 19~34세)을 위한 맞춤 예적금 추천 서비스다. 정부 청년정책 상품과 시중은행 예적금을 한곳에 모아, 사용자가 **가입할 수 있는 상품만 거르고** **나에게 맞는 순 / 실제로 받을 수 있는 금리 순**으로 정렬해 보여준다.

슬로건: "청년들의 금융 고민을 끝내다"

## 해결하려는 문제

자체 설문(61명)으로 확인한 세 가지 문제를 출발점으로 삼았다. 61명은 시장 규모를 증명하는 표본이 아니라 가설 검증용이다.

| 문제 | 근거 | 대응 기능 |
| --- | --- | --- |
| 정보 과부하·분산 | 정부·은행 상품 채널이 나뉘어 있음. 탐색 어려움 75% | 정부+은행 통합 리스트, 자격 자동 필터 |
| 우대금리 불투명 | 광고 최고금리와 실제 달성 금리가 평균 1~3%p 차이. 수익률 계산기 필요 97% | 탭 B 달성 가능 금리, 수익률 계산기 |
| 금융 용어 이해 어려움 | 용어 어려움 57%, 약관 미독 43% | 전역 금융 용어 풀이 (FE) |

설문에서 정렬 가중치의 근거도 가져왔다. Q12 중요도는 월 납입액 4.39, 저축 기간 4.38, 핵심 혜택 4.30 순이고, Q5 관심 항목은 금리 수준 84%, 우대조건 달성 용이성 59%, 세후 수령액 51% 순이다.

## 해결 방식: 3단계 추천

1. **정보 입력**: 1단계 키워드 선택(적합도용) + 2단계 수동 입력(자격 요건용). 자세한 내용은 [Y3-1 정보 입력](y3-1-input.md).
2. **자격 요건 자동 필터링**: 가입 불가 상품을 리스트에서 완전히 뺀다(Hard Filter).
3. **정렬**: 탭 A "나에게 맞는 순"(적합도 100점) / 탭 B "내가 받을 수 있는 금리 순". 자세한 내용은 [Y3-2 추천 리스트](y3-2-recommendation-list.md).

정부 상품과 은행 상품은 비교 지표가 다르다. 정부 상품은 **정부 기여금 환산 수익률**, 은행 상품은 **기본금리 + 실제 충족 가능한 우대금리**로 비교하고, 두 지표를 한 줄로 섞어 정렬하지 않는다(섹션 분리).

## 원칙

- **중립 정렬**: 추천 정렬에 광고비를 반영하지 않는다.
- **비중개**: Y-Fin.은 판매·중개 주체가 아니다. 신청은 기관 공식 페이지 아웃링크로만 연결하고, 은행 CTA에 로고를 쓰지 않는다(금소법상 중개 재분류 리스크 차단).
- **점진적 정보 수집**: 회원가입은 SNS 로그인만으로 끝내고, 민감한 금융 정보는 추천이 필요한 시점에 사용자가 원할 때 받는다.
- **근거 있는 수치만 표시**: 카드의 수치는 산출 기준(매칭 방식, 월 납입액, 만기, 조회 시점)과 함께 표시한다.

9월 출시 스코프를 정한 배경과 주차별 일정은 노션 「서비스 기획 피봇팅」에 있다. 핵심 전제는 다음 세 가지다.

1. 알림은 이메일 우선, 웹 푸시·알림톡은 fast-follow (FCM·토큰 관리가 최대 변수)
2. 캘린더는 라이브러리·기존 DB 활용
3. 파킹 공시 약관, 온통청년 날짜 필드를 먼저 검증

## 제품에 들어간 AI

- **데이터 파이프라인 보강**: 금감원 API의 비정형 우대조건 텍스트를 Gemini 2.5 Flash-Lite로 구조화한다. 달성 가능 금리 계산의 전제다. 캐시(SHA-256 요청 해시)·재시도·스키마 검증·규칙 기반 폴백을 두고, 사용자 정보는 보내지 않는다. 수집기(Fin-API)가 담당한다.
- **전역 금융 용어 풀이**: 어려운 용어를 쉬운 말로 풀이한다. 프론트엔드 기능이다.

약관 3줄 요약(구 Y4-1)은 정보 왜곡 책임 우려로 삭제했고, 용어 이해 문제는 용어 풀이로 대응한다.

## 시스템 구성

| 구분 | 스택 |
| --- | --- |
| Frontend (Fin-FE) | React 19 + Vite 7, Tailwind 4 |
| Backend (Fin-BE, 이 저장소) | Java 21 + Spring Boot 4.0.3, JPA, Security, OAuth2, JWT |
| Collector (Fin-API) | Spring Batch, 금감원·온통청년 API, Gemini 2.5 Flash-Lite 정규화 |
| Infra / DB | AWS EC2 + RDS, PostgreSQL 16, Docker Compose, Sentry, GA4 |

백엔드 구조는 [구현: 아키텍처](../implementation/architecture.md)에서 다룬다.

## 팀 역할

기획 1, 디자인 1, 백엔드 2, 프론트엔드 1. 백엔드는 User·Term·Category·Search 도메인(자격 필터·정렬)과 Auth·Data 도메인(OAuth2·JWT·외부 API 전처리)으로 나눠 맡았다.
