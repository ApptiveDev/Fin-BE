# A1~A3 상품 추천 확장 (정보입력·필터, 파킹통장, 단기 예적금)

> 상태: 구현 중 (draft PR #36, #37, 2026-10-18 기준) · 원본: 노션 「A1 ~ A3 기능 PRD」(개정본), 「추천 로직 통합 명세 (A1 ~ A3 포함)」, 「서비스 기획 피봇팅」

## 개요

- 정부 정책상품과 은행 상업상품이 한 화면에서 비교되지 않고, 정책상품은 인지 대비 가입이 낮다(청년도약계좌 인지율 76.0%, 가입 유지자는 청년 전체의 0.72%. 서민금융진흥원 『2024년 청년금융 실태조사』, 2025.3).
- 파킹통장은 예치금 한도와 구간별 우대금리가 상품마다 달라 최고금리를 오인하기 쉽다.
- 해결 방향: 정책·상업 상품을 한 폼으로 매칭하고, 금리(%)가 아니라 세후 실수령액으로 비교한다. 대분류를 단기예치 / 목돈만들기로 나누고(내집준비는 예정), 실수령액순·기여금 총액순 정렬로 왜곡을 줄인다.
- 9월 스코프에서 A1~A3는 Batch 1 "상품 추천 확장"(기존 추천 엔진 확장)으로 묶인다. A1은 A2·A3의 전제다.

## A1. 정보입력·필터 확장

### 배경

- 기존 폼은 저축기간, 예치액, 월납입을 각각 받아 칩과 필드가 많았고, 예금과 적금을 서로 다른 금액 기준으로 계산해 세후 실수령액 정렬이 무의미해지는 문제가 있었다.
- 개정 구조는 저축기간을 라우터로 써서 진입 대분류를 정하고, 대분류마다 금액 1개만 받는다. 다른 상품유형의 원금은 정규화로 파생해 같은 기준으로 비교한다.
- 추가 화면 없이 기존 폼을 확장한다(대분류 세그먼트에 맞춘 단일 합집합 폼).

### 입력 항목

| 단계 | 필수 | 선택 |
| --- | --- | --- |
| 1단계 입력 (비로그인) | 저축기간, 금액 | 은행우대, 현재신분, 핵심혜택 |
| 2단계 입력 (로그인) | 생년월일, 개인소득, 가구소득, 거래이력 | 거주지역, 근속 |

- 저축기간: 단일 선택, `save_trm`에 정확히 매핑되어 대분류와 금액 필드를 결정
- 금액: 단기 예치 희망액 10만~1억 원 / 목돈 월 납입 희망액 1만~100만 원
- 대분류 세그먼트(단기예치 | 목돈만들기): 결과 상단에서 전환

### 입력 → 소비처

| 입력 | 쓰이는 곳 |
| --- | --- |
| 저축기간 | 대분류 라우팅, 정렬 기간 필터(`save_trm`), 정규화 기간 |
| 금액(예치액 / 월저축액) | 세후 실수령액, 납입·예치 한도 적합도, 예금↔적금 정규화 기준 |
| 은행우대, 거래이력 | 달성 가능 금리 (탭 B, 예적금 탭) |
| 현재신분, 핵심혜택 | 목돈 적합도 (탭 A) |
| 소득, 가구소득, 근속, 거주지역 | 목돈 자격 필터, 정부 기여금 |

### 사용자 흐름

1. 저축기간 선택 → 진입 대분류와 금액 필드가 자동으로 정해짐
2. 대분류에 맞는 금액 1개 입력(예치액 또는 월저축액)
3. 기본 탭 확인 후 세그먼트로 반대 대분류 전환, 누락 금액은 인라인 보완
4. 실수령액·개인화 값을 보려고 로그인

### 기능 요구사항

- 저축기간을 고르는 즉시 대분류와 금액 라벨이 바뀌어야 한다. 목적과 무관한 필드는 노출하지 않는다.
- 금액은 대분류 종속 단일 필수. 유효 범위를 벗어나면 인라인 오류.
- 결과 세그먼트를 전환했는데 그 대분류 금액이 없으면 계산하지 않고 인라인 입력 배너를 띄운다.
- 비로그인 입력값은 로그인 후 프로필로 자동 승계한다(중복 입력 방지).

### 기술 요구사항

- 대분류 라우팅: 저축기간 → `save_trm` 매핑(`{1,3}` = 단기, `{6,12,24,36}` = 목돈) → 클라이언트 대분류 상태 결정. 세그먼트 전환은 대분류 상태를 덮어쓰고 금액 유무를 검사한다.
- 조건부 금액 필드: 대분류 상태에 따라 예치액 / 월저축액 중 하나만 렌더링. 범위(예치 10만~1억, 월 1만~100만)는 클라이언트에서 검증.
- 정규화 파라미터: 추천 계산 요청에 대분류, `save_trm`, 금액을 보낸다. 목돈은 (월저축액, 기간), 단기는 (예치액). 예금↔적금 파생 원금은 서버에서 계산.
- 비로그인 상태 보존: 1단계 입력값을 Local Storage에 저장하고, 로그인 성공 시 서버 프로필로 1회 전송·매핑.
- 개인정보 처리 분리: 1회성 시뮬레이션 처리와 저장 프로필 동의를 분리(개인정보 동의 구조와 연동). 저장 항목은 자격 7개 + 추천조건 5개로 한정.
- 세그먼트 전환 상태: 두 대분류 결과를 각각 캐시. 전환 시 재계산을 최소화하고 누락 금액만 추가 요청.

### 지표

- 북극성: 전체 유입 대비 정보 입력 완료 전환율 (목표안 25% 이상)
- KPI: 평균 입력 소요 시간 (목표안 60초 이내) / 단계별 이탈률, 저축기간 → 금액 → 결과 진입 (목표안 이전 단계 대비 15% 이내) / 입력 금액이 상품 납입·예치 한도 유효 범위 안에 있는 비율
- 보조: 대분류 세그먼트 전환율, 인라인 보완 입력 완료율

## A2. 파킹통장 (단기예치, 파킹통장 탭)

### 배경

- 단기예치의 파킹통장 탭을 시중은행 파킹통장으로 구성한다. 비로그인 노출, 단기 기본 활성 탭.
- 파킹 44개의 기본금리 중앙값은 0.10%로 변별력이 없다. 실질 비교축은 최고금리와 그 금리가 적용되는 한도다.

### 상세 규칙

- 데이터: 제1금융권 파킹통장 44건. 필드 `base_rate`, `max_rate`, 구간 조건, 예치 한도.
- 최고금리 산출 분기: 단일금리 31건은 공시값 / 구간금리 11건은 최고 적용구간 / 크롤링 4건은 개별 산출.
- 정렬: `max_rate`(우대 포함 최고금리) 내림차순, 서버 정렬. 동점이면 `base_rate` 내림차순 → `product_name`. 예금자보호는 1금융 1억으로 균일해 tie-break에 쓰지 않고 표시만 한다.
- 카드 표시(필수): 최고금리와 적용 한도 병기, 예금자보호 1억 배지, 이자지급방식.
- TOP3: 최고금리 상위 3개.
- 오인 방지 툴팁(상시): 우대 포함 최고금리 순이며, 금액 구간별 적용 한도와 이벤트 우대가 다르다는 안내.
- 인증: 비로그인 접근 허용. 인증 미들웨어에서 파킹통장 탭을 예외 처리.
- 아웃링크: `apply_url` 커버리지 점검 필요. 없으면 수동 매핑 테이블을 만든다(FSS 은행상품 `apply_url` 0% 전례). 매핑 소스는 자동 / 수동 이원화로 관리.

### 사용자 흐름

1. 비로그인으로 단기 진입 → 파킹통장 탭이 기본 노출
2. 최고금리 + 적용 한도 카드로 비교, 툴팁 확인
3. 상품 상세 → 아웃링크로 은행 이동

### fast-follow: 실수령액 정렬

1. 예치기간 입력 도입 (파킹은 만기가 없으므로 예상 예치기간)
2. 구간금리 정규화: 조건 텍스트(44건 중 23건) 스키마화, 상시 우대와 이벤트 우대 분리
3. 예치금 → 구간 적용금리 + 우대 → 실수령액 산출
4. 실수령액순으로 전환하고 QA. 최고금리순은 보조 탭으로 유지

- 스키마: 예치기간 입력 필드 + 구간금리 정규화 테이블(상시 / 이벤트 우대 분리) → 실수령액 산출 파이프라인 추가.

### 지표

- 북극성: 파킹통장 → 아웃링크 전환율
- KPI: 한도 툴팁 확인율, TOP3 카드 클릭률, 파킹 → 다른 탭·로그인 이동률(비로그인 유입의 후속 행동)
- 보조: 최고금리 구간 상품의 상세 진입 후 이탈률

## A3. 단기 예적금 (단기예치, 예적금 탭)

### 배경

- 단기예치의 예적금 탭을 3개월 이하 정기예금·적금으로 구성한다. 로그인 노출.
- 같은 금리라도 예금이 적금보다 실수령이 약 1.8배 크므로 금리(%)로 비교하면 왜곡된다.
- 데이터 규모: 초단기 예금 27개, 적금 11개 상품(선택 기간 필터 후 레코드 기준 예금 46, 적금 18). 적금 우대격차 중앙값이 1.73%p로 커서 우대 반영이 실수령액에 의미 있다.

### 상세 규칙

- 대상: 예적금 데이터 중 `save_trm` ∈ {선택값(1 또는 3)}. 예금(`DEPOSIT`)과 적금(`SAVING`)을 한 집합으로 묶는다.
- 입력: 단기 금액(예치 희망액) 하나만 쓴다. 적금 월납입 = 예치액 ÷ `save_trm`, 서버에서 파생. 예금과 적금의 총투입원금이 같아진다.
- 금리: 달성 가능 금리 = `base_rate` + 적용 우대(1단계 입력 은행우대 + 자동 적용 비대면·연령 + 거래이력 첫거래·재예치). 매칭하지 못한 우대는 적용하지 않는다.
- 우대 커버: 초단기 상품 우대 33개 중 23개(70%)를 은행우대, 거래이력, 생년월일로 커버.
- 산식 (P = 예치액, r = 연 금리, n = `save_trm`):
  - 예금 이자 = P × r × (n / 12)
  - 적금 이자 = (P / n) × (r / 12) × n(n+1) / 2
  - 세후 = 이자 × (1 − 0.154), 세율 상수 0.154
- 정렬: 세후 실수령액 내림차순 고정, 예·적금 혼합, 서버 정렬. 정렬 토글 없음.
- 필터칩: 전체 / 예금 / 적금.
- TOP3: 세후 실수령액 상위 3개.
- 카드 표시(필수): 세후 실수령액(강조), 적용 금리, 기간, 예금/적금 배지, 납입방식(적립형/예치형)과 기준액, 적금 월한도, 예금자보호.
- 정렬 유효성: 저축기간 필수라 같은 기간 집합만 비교한다. 같은 금리에서 예금이 구조적으로 유리하므로 필터칩과 납입방식 라벨로 오인을 막는다.
- 로그인 게이팅: 실수령액 응답은 인증 필수. 비로그인 요청은 금리·상품명까지만 반환하고 실수령액 필드는 마스킹.
- 아웃링크: `apply_url` 매핑. FSS 은행상품 커버리지 0%이므로 수동 매핑 테이블 필수.

### 사용자 흐름

1. 예적금 탭 진입, 실수령액을 보려고 로그인
2. 세후 실수령액순 확인, 필터칩으로 상품유형 좁힘
3. 상품 상세 → 아웃링크로 은행 이동

### 지표

- 북극성: 초단기 예적금 → 아웃링크 전환율
- KPI: 예금 대비 적금 선택 비율(필터·라벨이 선택을 왜곡하지 않는지), 로그인 전환율, TOP3 카드 클릭률
- 보조: 필터칩 사용률, 납입방식 라벨 노출 대비 상세 진입률

## 열린 이슈

- 파킹통장 정렬 기준 충돌: 「서비스 기획 피봇팅」의 경량 스펙은 "기본금리·최고금리 2컬럼, 정렬은 기본금리 기준"이고, 이후 개정된 A2 PRD는 `max_rate` 내림차순 정렬이다. 이 문서는 A2 PRD(개정본)를 따른다.
- 파킹 데이터 원천: 피봇팅 문서는 은행연합회 소비자포털(크롤러 신규), A2 PRD는 "제1금융권 44건, 단일 31 / 구간 11 / 크롤링 4"로 적혀 있어 수집 경로별 비중이 명확하지 않다.
- A3 명칭과 범위: 피봇팅 문서는 "초단기예금(3개월 이하)", A3 PRD는 예금과 적금을 모두 포함한다. 이 문서는 A3 PRD를 따른다.
- 목돈 탭 B 정렬: 공통 전제는 "탭 B 세후 실수령액순"이다. `main`의 탭 B는 달성 가능 금리 순이고, PR #36이 세후 실수령액 순으로 바꾼다.
- 미성년 기준: PR #36(원본 해커톤 PR)은 `age < 17`로 구현했다. 기획 기준과 맞는지 확인이 필요하다(PR #37 비고).
- 실수령액 정의: "세후 실수령액"이 원금을 포함한 금액인지 세후 이자만인지 원본에 명시되지 않았다(같은 원금 비교라 정렬 결과는 같음, 표시값은 달라짐).
- 저장 프로필 항목: "자격 7 + 추천조건 5"의 구체 항목 목록이 원본에 없다.
- 「추천 로직 통합 명세 (A1 ~ A3 포함)」는 노션 내보내기에 Google Sheets 링크만 있어, 시트 내용(세부 산식·우대 매칭표 등)은 이 문서에 반영되지 않았다. 배점은 PR #36 구현에서 확인한 값을 아래 "구현 진행 상황"에 적었다.
