# Y5 마이페이지 (찜해둔 Fin., 개인정보)

> 원본: 노션 「Y5 마이페이지 PRD (Y5-1, Y5-2 포함)」 (2026-07, B2 연동 변경 2026-10-09 반영)

## 개요

저축 상품은 자주 쓰는 서비스가 아니다. 마이페이지는 **입력 정보 재사용**과 **찜한 상품 비교**로 사용자가 돌아올 이유를 만드는 리텐션 허브다.

- **Y5-1 찜해둔 Fin.**: 관심 상품을 하나의 캐러셀에서 좌우로 비교하고 [상세 보기]로 상세에 간다.
- **Y5-2 개인정보**: 변동성이 낮은 자격 정보 6개를 읽기 전용으로 보여주고, 수정은 정보 입력 화면으로 보낸다.
- **Y5-3 내 알림**: B2 알림 기획에서 추가된 탭이다. [B2 알림](b2-notification.md) 참고.

설계 원칙:

1. 마이페이지에서 직접 편집하지 않는다. 입력 검증과 동적 제어는 Y3-1 한 곳에만 둔다.
2. 화면 표시는 6개지만 저장·프리필은 입력값 12개 전부 유지한다.
3. 찜 카드 수치는 찜한 시점의 스냅샷이 아니라 **조회 시점에 다시 계산**한다.
4. 산정 기준이 다른 지표(기여금 환산 수익률과 달성 가능 금리)는 라벨과 안내로 혼동을 막는다.
5. 찜 카드에는 신청 아웃링크를 두지 않는다. [상세 보기]로 Y4 상세에 보내서 그곳에서 신청하게 한다.

## Y5-1 찜해둔 Fin.

### 저장 규칙

| 항목 | 규칙 |
| --- | --- |
| 찜 대상 | 정부: 상품 코드 / 은행: 상품 코드 + 저축 기간. 금감원 상품은 기간별로 최대 6개 레코드가 있어 기간이 없으면 금리를 특정할 수 없다 |
| 중복 | (사용자, 상품, 기간) 유니크. 같은 상품 다른 기간은 별개 찜 |
| 한도 | 최대 20개. 넘으면 추가 불가 안내 (409) |
| 비로그인 | 찜 버튼을 누르면 로그인 유도 모달 |

### 카드

| 영역 | 정부 카드 | 은행 카드 |
| --- | --- | --- |
| 공통 | 적합도·특성 태그, 상품명 + 찜 하트(해제), 요약줄(정부 지원·만기·월 납입 범위) | 같은 구성, 요약줄은 은행명·만기·월 납입 범위 |
| 지표 | 기여금 환산 수익률, 예상 만기 기여금 총액 | 기본금리, 최고금리 |
| 하이라이트 | 계산 기준 캡션 (매칭 방식, 내 월 납입액, 만기) | **내가 달성 가능한 금리** 칩 (조회 시점 재계산) |

- 캐러셀은 3장 노출 + 좌우 화살표(모바일 스와이프). 찜 등록 최신순, 정부·은행 그룹 분리나 필터 없음.
- 캐러셀 상단 고정 안내: "기여금 환산 수익률과 달성 가능 금리는 산정 기준이 달라 직접 비교할 수 없어요".
- 0개일 때: "아직 찜한 상품이 없어요" + [추천받으러 가기]. 이때는 비교 안내 배너와 비중개 고지를 숨긴다.
- 섹션 하단에 비중개 고지를 항상 둔다.

### 재계산 규칙

| 항목 | 규칙 |
| --- | --- |
| 금리·기여금 | 조회 시점 최신 배치 데이터로 계산 |
| 적합도·달성 가능 금리 | 최신 저장 프로필 기준. 정보를 수정하면 카드 값도 바뀐다 |
| 계산 기준값 | 내 월 납입 희망액·저축 기간 |
| 신청 불가 상태 | 정부는 모집 종료(`recruit_closed`), 은행은 판매 종료(`sale_ended`). 카드를 지우지 않고 상태와 마지막 확인일을 표시 |

### API 초안 (기획)

- `POST/DELETE /favorites`: 상품 코드, 저축 기간(은행만). 응답에 현재 찜 개수.
- `GET /me/favorites`: 최신 데이터와 최신 프로필로 적합도·환산 수익률·달성 가능 금리를 서버에서 다시 계산해 반환. `source_code`를 넣어 FE 라벨 분기 기준으로 쓴다.

실제 구현된 엔드포인트는 [상세·계산기·찜 구현](../implementation/detail-calculator-favorites.md)을 본다.

### 이벤트

`wishlist_add`, `wishlist_remove` (속성: `product_code`, `source_code`, `save_trm`, `entry_point`), `wishlist_card_impression`, `wishlist_empty_view`, `wishlist_empty_cta_click`. 마이페이지 경유 신청은 찜 카드 [상세 보기] → 상세의 `apply_outlink_click`(유입 `mypage_wishlist`)으로 잰다.

## Y5-2 개인정보

### 표시 필드 6개 (읽기 전용)

| 필드 | 표기 |
| --- | --- |
| 생년월일 | YYYY.MM.DD + 만 나이 (조회일 기준 서버 계산) |
| 개인 연 소득 | 만 원 단위 |
| 가구원 수·가구 소득 | 선택 구간 그대로(60~180% 이하) + 가구원 수 기준 금액 가이드 |
| 거주 지역 | 시도명 |
| 우대조건 (선호) | 은행 거래 우대 태그 그대로 |
| 거래 이력 | 은행명 단위 (첫거래: OO, OO / 재예치: OO). 개수로 집계하지 않는다 |

### 표시하지 않지만 저장·프리필은 유지하는 6개

월 납입 희망액, 저축 기간, 핵심 혜택(세션마다 바뀌는 값), 현재 신분(동적 제어와 결합), 근속 기간(매월 변함), 무주택·세대주(청약 전용 후속 질문과 결합).

하단 캡션: "월 납입 희망액·저축 기간 등 나머지 입력값도 저장되어 다음 추천 시 자동 반영돼요. (이 화면에는 표시되지 않아요)"

### 편집

섹션 우상단 단일 CTA [정보 수정하러 가기] → `/input?from=mypage`. 저장값 12개를 모두 채운 상태로 정보 입력 화면을 열고, 수정을 마치면 마이페이지로 돌아와 찜 카드 수치를 다시 계산한다.

## B2 연동으로 바뀐 점 (2026-10-09)

아직 구현되지 않은 기획이다. 마이페이지 탭이 찜해둔 Fin. / 내 알림 / 개인정보 3개가 되고, 찜 카드 하단 버튼이 상태별로 나뉜다.

| 상품·상태 | 왼쪽 | 오른쪽 |
| --- | --- | --- |
| 정부, 모집 전·예정·중 | [상세 보기] | [알림 받기] |
| 정부, 알림 설정함 | [상세 보기] | `알림 받는 중` |
| 정부, 다음 회차 미정·상시 | [상세 보기] (전체 폭) | 없음 |
| 은행, 가입 등록 전 | [상세 보기] | [가입했어요] → 가입 등록 모달 |
| 은행, 가입 등록 후 | [상세 보기] | `가입함 · 만기 D-n` |

찜 아래에 "내 가입 상품" 목록이 생기고, 만기 30·7일 전 알림이 자동 설정된다. 찜을 해제해도 알림과 가입 상품은 남는다. 자세한 규칙은 [B2 알림](b2-notification.md).
