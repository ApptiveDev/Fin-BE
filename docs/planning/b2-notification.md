# B2 알림

> 상태: 기획 (미구현) · 원본: 노션 「B2 알림 PRD」, 「B2 알림 기능 명세」(2026-10-05), 「서비스 기획 피봇팅」

## 개요

- 유저가 고른 정책 회차의 마감·시작과 본인이 가입한 상품의 만기를 이메일로 알려 서비스로 다시 데려오는 기능. 리텐션 엔진의 '복귀' 축이고, B1 캘린더가 '탐색' 축이다.
- 배경
  - 저축상품은 가입 후 만기까지 다시 볼 이유가 적은 저빈도 카테고리다. 현재 리텐션 장치는 찜(Y5-1)과 입력 정보로 재추천(Y5-2)뿐이고, 떠난 유저를 다시 부를 수단이 없다.
  - 정책상품은 모집 기간을 놓치면 다음 회차까지 6개월~1년을 기다려야 한다.
  - 은행 예적금은 상시 모집이라 모집 기간이 없지만, 만기에 재비교 없이 자동 재예치되거나 방치되기 쉽다. 다른 서비스의 만기 일정은 마이데이터 연결이 전제라 Y-Fin은 같은 방식을 쓸 수 없다.
- 핵심 결정
  - 유저는 발송 시점을 고르지 않는다. [동의하고 알림 받기] 한 번이면 Y-Fin이 정한 시점에 자동 발송.
  - 채널은 이메일만. 웹 푸시·알림톡은 FCM·토큰 관리가 일정상 최대 리스크라 fast-follow.
  - 알림 설정 단위는 회차. 정보성 범위로 한정한다.
  - 은행 상품은 유저가 '가입했어요'로 셀프 등록하면 만기를 계산해 알린다.
  - 이메일을 놓친 유저를 위해 사이트 리마인드 배너를 보조로 둔다.
  - B1에서 일정을 보고 알림을 설정하고, 알림을 받아 상세·신청으로 돌아오는 리텐션 루프를 만든다.
- 9월 스코프에서 Batch 2 "리텐션 기능"에 속하며 공수 판정은 "최대 리스크"(알림 인프라 신규).

## 범위

- 포함: 마감·시작·만기 알림(이메일), 이메일 인증, 원클릭 설정, 리마인드 배너, 마이페이지 내 알림, 찜해둔 Fin. 카드·가입 등록·만기 알림, 수신거부
- 제외: 웹 푸시, 카카오 알림톡, 알림을 설정하지 않은 신상품 안내(광고성), 주거 정책, 내집마련
- fast-follow: 웹 푸시, 알림톡 (마이페이지에 `준비 중`으로 자리만 둠)
- 우선순위: P0 출시 필수 / P1 출시 목표, 밀리면 fast-follow / P2 출시 후

## 용어

| 용어 | 정의 |
| --- | --- |
| 대상 | 정책 회차 또는 가입 상품 |
| 알림 설정 | 유저가 대상 1개의 알림 1종을 받겠다고 신청한 것. 화면 문구는 `설정해둔 알림`, `알림 받는 중`, `알림 끄기`로 통일 |
| 발송 시점 | 기준일(마감일, 시작일, 만기일)보다 며칠 전에 보내는지. 유형별 고정 |
| 다이제스트 | 같은 날 보낼 알림 여러 건을 1통으로 묶은 메일 |
| 인증 | 첫 알림 설정 때 받을 이메일이 본인 것인지 메일 링크로 확인하는 것 |
| 1계층 / 2계층 | Y-Fin 정책상품 / 청년 금융 지원 정책 (B1 문서 참고) |

화면 ID 참고: Y3-1 정보 입력, Y3-2 추천 결과, Y4 상품 상세, Y4-2 신청 페이지, B1-05 로그인 유도 모달.

## 알림 유형과 발송 시점

| 유형 | 대상 | 발송 시점 (자동, 오전 9시) |
| --- | --- | --- |
| 마감 알림 | 1·2계층 마감 전 회차 (연중 접수·상시 제외) | 마감 7일·3일·1일 전 |
| 시작 알림 | 1·2계층 시작 전·모집 예정 회차 | 시작 전날·당일 |
| 만기 알림 | 셀프 등록한 가입 상품 (정부·은행) | 만기 30일·7일 전 |

- 발송일 = 기준일 − 발송 시점. 발송 시각은 오전 9시 고정(야간 발송 없음).
- 시점 근거: 마감 7일 전은 서류 준비, 3일 전은 재확인, 1일 전은 마지막 기회. 시작 알림은 신청이 열린 날 바로 행동하게 함.
- 알림을 설정할 때 이미 지난 시점은 건너뛴다. 남은 시점이 없으면 설정할 수 없다(시작·만기도 같은 원칙).
- 회차가 끝나면 알림 설정도 끝난다.
- 2계층은 찜·Y4 상세가 없으므로 B1 캘린더에서만 알림을 설정한다.

늦게 알림을 설정한 경우 (마감 알림)

| 설정 시점 | 받는 알림 |
| --- | --- |
| 마감 8일 이상 전 | 7일·3일·1일 전 모두 |
| 마감 4~7일 전 | 3일·1일 전 |
| 마감 2~3일 전 | 1일 전 |
| 마감 1일 전 오전 9시 전 | 그날 1일 전 알림 |
| 마감 1일 전 오전 9시 후, 마감 당일 | 없음 → 설정 불가. `오늘 마감이에요` 또는 `내일 마감이에요`, 옆 [상세 보기] 강조 |
| 회차 종료 후 | 알림 버튼 숨김. 찜 상태면 다음 회차가 열릴 때 리마인드 배너로 `다음 모집도 알려드릴까요?` |

- 시작 당일 오전 9시가 지나 보낼 시작 알림이 없으면 마감 알림으로 설정하고 토스트 `시작 알림 시점이 지나 마감 알림으로 받아요`.

예시 타임라인

```
회차: 부산 청년 신용회복 지원금 (09.22 ~ 10.21) · 10.05 알림 설정

10.05  [동의하고 알림 받기] → 이메일 인증 → 받는 중
10.14  오전 9시  "마감까지 7일 남았어요"   (같은 날 다른 알림과 묶음)
10.18  오전 9시  "마감까지 3일 남았어요"
10.20  오전 9시  "내일 신청이 마감돼요"
10.22  회차 종료 → 알림 설정 종료
```

## 사용자 흐름

### 대표 여정

1. 알림 설정: 캘린더, 찜 직후 토스트, 찜해둔 Fin.에서 [알림 받기] → [동의하고 알림 받기] → 이메일 인증
2. 수신: 오전 9시 메일 또는 접속 시 리마인드 배너 → [상세 보기]
3. 복귀: Y4 상세 확인 → Y4-2 신청 페이지
4. 가입 등록: 찜해둔 Fin. 카드 [가입했어요] → 가입일·기간 입력 → 만기 알림 자동 설정
5. 만기 복귀: 만기 메일 또는 내 가입 상품 [만기 수익률 계산하기] → [다음 가입 상품 추천받기] → 이전 입력값이 채워진 추천 결과(Y3-2)
6. 해지: 메일 하단 [알림 설정 관리] → 로그인 → 내 알림에서 하나씩 끄기(권장). 모두 끌 때만 메일 [전체 수신거부](로그인 없이)

### 알림 설정 진입점

| 위치 | 설정되는 알림 |
| --- | --- |
| B1 캘린더 일정 카드, 리스트, 모바일 카드 | `시작` 일정은 시작 알림, `마감` 일정은 마감 알림 (1·2계층 공통) |
| 찜 직후 토스트 (B2-03, Y3-2·Y4 상세) | 모집 중이면 마감, 모집 전·예정이면 시작 |
| 마이페이지 찜해둔 Fin. 정책상품 카드 [알림 받기] | 모집 중이면 마감, 모집 전·예정이면 시작 |
| B1 빈 상태 [다음 모집 알림 받기] | 가장 가까운 예정 회차의 시작 알림 |
| 찜해둔 Fin. 은행 상품 카드 [가입했어요], 내 가입 상품 [+ 가입 상품 등록] | 만기 알림 |

## 기능 요구사항·상세 규칙

### 1. 알림 버튼·알림 설정 (P0)

모든 진입점(B1 카드·리스트·모바일, 찜해둔 Fin., 내 알림, 내 가입 상품)에서 같은 알림 버튼 컴포넌트를 쓴다.

| 상태 | 조건 | 문구 | 누르면 |
| --- | --- | --- | --- |
| 기본 | 로그인, 알림 설정 전 | `알림 받기` | 첫 설정은 B2-01, 이후는 원클릭 |
| 받는 중 | 알림 설정함 | `알림 받는 중` | 작은 메뉴: 보낼 날짜, 받는 곳, [알림 끄기] |
| 인증 대기 | 첫 설정 후 미인증 | `인증 대기 중` | 작은 메뉴: 인증 안내, [인증 메일 다시 받기], [이메일 변경] |
| 비로그인 | | `로그인하고 알림 받기` | 로그인 유도 모달 |
| 불가 (남은 시점 없음) | 마감 당일 등 | `오늘 마감이에요` | 옆 [상세 보기] 강조 |
| 불가 (한도) | 받는 중 30건 | `알림 받기` 비활성 | 토스트 `알림은 최대 30개까지 설정할 수 있어요` |
| 숨김 | 상시, 연중, 다음 회차 미정 | 버튼 없음 | |

- 설정할 수 없는 일정은 숨기고, 일시적으로 설정할 수 없는 경우(오늘 마감, 한도)만 비활성.
- 리스트·모바일은 아이콘 3단계(기본, 받는 중, 불가)로 줄인다.
- 알림 유형은 누른 일정을 따른다: `시작` 일정은 시작 알림, `마감` 일정은 마감 알림(1·2계층 공통).
- 같은 회차·같은 유형은 중복 생성하지 않고 `이미 알림을 받고 있어요`. 받는 중 알림은 1인 30건까지.
- 작은 메뉴는 화면 이동 없이 버튼 바로 아래 열리고, 바깥을 누르면 닫힌다.
- [알림 끄기]를 누르면 버튼이 `알림 받기`로 돌아오고 토스트 `알림을 껐어요` + [실행 취소].
- B1 캘린더의 `만기` 일정도 같은 버튼. 가입 등록 때 자동 설정되므로 `알림 받는 중`.
- 비로그인이 누르면 로그인 유도 후 원래 화면에서 설정을 이어서 진행.

알림 설정 상태 전이

| 상태 | 언제 | 보이는 모습 |
| --- | --- | --- |
| 인증 대기 | 첫 알림 설정 후 이메일 인증 전 | `인증 대기 중` |
| 받는 중 | 인증 완료 후 | `알림 받는 중` |
| 일시정지 | 마이페이지 전체 알림 끔, 메일 전체 수신거부 | 토글 꺼짐. 다시 켜도 지난 알림은 보내지 않음 |
| 종료 | 모든 시점 발송 완료, 회차 종료, 만기일 지남 | 설정해둔 알림에서 빠짐 |
| 해지 | 유저가 끔, 7일간 미인증, 탈퇴 | 설정해둔 알림에서 빠짐 |

### 2. 알림 받기 모달·이메일 인증 (P0)

- 첫 알림 설정에만 모달(B2-01)을 띄운다. 체크박스 없이 [동의하고 알림 받기] 클릭이 동의다.

| 순서 | 영역 | 내용·규칙 |
| --- | --- | --- |
| 1 | 제목 | `마감 알림 받기` / `시작 알림 받기` |
| 2 | 대상 요약 | 유형과 D-day, 계층, 상품명, 신청 기간, 기관 (읽기 전용) |
| 3 | 이렇게 알려드려요 | 실제 발송 날짜 목록, 예: `D-7 · 10월 14일 (수) 오전 9시`. 선택 없음, 지난 날짜 제외 |
| 4 | 받을 이메일 | 계정 이메일 + [변경]. 계정에 이메일이 없으면 빈 칸, 필수 입력 |
| 5 | 인증 안내 | 처음이면 인증 메일을 보낸다는 안내 |
| 6 | 동의 고지 | 버튼을 누르면 안내 메일 수신에 동의한다는 고지 |
| 7 | 버튼 | [취소], [동의하고 알림 받기]. 완료 후 토스트 |

- 문구: 발송 안내 `마감 7일 · 3일 · 1일 전에 자동으로 보내드려요. 이미 지난 시점은 건너뛰어요.` / 인증 안내 `처음 신청하면 인증 메일을 보내드려요. 인증 후부터 알림이 발송돼요.` / 동의 고지 `[동의하고 알림 받기]를 누르면 이 일정의 안내 메일 수신에 동의하게 돼요. 마케팅 정보 수신과는 별개이며, 메일 하단이나 마이페이지에서 언제든 끌 수 있어요.` / 완료 토스트 `메일함에서 인증을 완료하면 알림이 시작돼요`
- 인증 규칙: 인증 메일 링크를 누른 뒤부터 발송. 링크는 24시간 유효. 7일간 미인증이면 알림 설정 취소. 재발송은 1분에 1번.
- 인증 메일(B2-10): 제목 2줄, 본문 1문장, 신청한 알림 요약(유형, 상품명, 보낼 날짜, 받을 이메일), [이메일 인증하기]. 본문에 `24시간 안에 눌러주세요`. 하단에는 해지 링크 대신 발신 안내와 `본인이 신청하지 않았다면 이 메일을 무시해 주세요`.
- 인증 결과 화면(B2-08): 로그인 없이 열리는 단독 화면, GNB 대신 로고만.

| 화면 | 열리는 때 | 내용 |
| --- | --- | --- |
| 인증 완료 | 인증 링크 클릭 (이미 인증한 링크를 다시 눌러도 같음) | `이메일 인증을 완료했어요`, 받을 알림 날짜 요약, [캘린더로 가기], `알림 설정 보기` |
| 링크 만료 | 24시간 지난 링크 | `링크가 만료됐어요`, 가린 이메일, [인증 메일 다시 받기] |
| 신청 취소 | 7일 미인증으로 취소된 뒤 링크 클릭 | `신청이 취소됐어요`, [캘린더로 가기] |

### 3. 원클릭 알림 설정 (P0)

- 인증을 마친 유저는 모달·확인 단계 없이 버튼 한 번으로 설정되고, 버튼은 `알림 받는 중`으로 바뀐다.
- 하단 토스트: `알림을 켰어요` / `{발송 날짜들} 오전 9시에 {이메일}으로 알려드릴게요` / [실행 취소]. 토스트가 떠 있는 동안 [실행 취소]로 되돌린다.

### 4. 알림 메일 발송 (P0)

- 오전 9시 고정 발송. 같은 유저의 같은 날 알림은 1통으로 묶는다(1건이면 단건, 2건 이상이면 다이제스트).
- 다이제스트 순서: 마감 D-n 가까운 순 → 시작 → 만기. 최대 10건, 넘으면 `외 n건은 Y-Fin에서 확인하세요`.
- 주 버튼은 1개, 유형에 맞는 상세(Y4) 또는 추천 결과로 보낸다. 2계층은 온통청년 페이지. 메일·배너에서 신청 페이지로 바로 보내지 않는다(상세 확인 후 신청 클릭률 측정).
- 본문에 금리·기여금 수치와 다른 상품 추천을 넣지 않는다(광고성 재분류 방지, 열람 시점과 수치가 달라질 수 있어 상세에서 최신값을 보게 함). 만기 메일도 특정 상품을 추천하지 않는다.

메일 구성 (위에서부터)

| 순서 | 요소 | 규칙 |
| --- | --- | --- |
| 1 | 로고, `일정 알림` | |
| 2 | 제목 2줄 | 남은 일수만 강조 |
| 3 | 본문 1문장 | 기간과 기준일을 문장으로 |
| 4 | 요약 카드 | 유형과 D-day, 상품명, 정보 3줄 |
| 5 | 주 버튼 1개 | 유형별 목적지 |
| 6 | 보조 링크 | `Y-Fin에서 내 일정 모두 보기`, `다음 알림 · {날짜} (D-n)` |
| 7 | 고지 | 기준일, 비중개, `이 메일은 회원님이 직접 신청한 일정 안내입니다.`, `알림을 하나씩 끄거나 다시 켜는 건 Y-Fin 내 알림에서 할 수 있어요.` |
| 8 | 하단 링크 | `알림 설정 관리`(내 알림), 작게 `전체 수신거부`, 발신자 정보. 개별 해지 링크 없음 |

| 메일 | 제목 | 본문 | 주 버튼 → 목적지 |
| --- | --- | --- | --- |
| 마감 7일·3일 전 | `[Y-Fin] {상품명} 신청 마감까지 {n}일 남았어요` | `{시작일}부터 신청을 받고 있어요. 마감은 {종료일}이에요.` | `상세 보기` → Y4 상세 (2계층은 `온통청년 보기`) |

| 다이제스트 | `[Y-Fin] 오늘 확인할 일정 {n}건` | `{날짜} 기준, 신청하신 알림을 한 번에 모았어요.` | `Y-Fin에서 모두 보기` → 마이페이지 |
| 인증 (B2-10) | `[Y-Fin] 알림 받을 이메일을 확인해 주세요` | `아래 버튼을 누르면 알림 설정이 완료돼요. 24시간 안에 눌러주세요.` | `이메일 인증하기` |

### 5. 해지·수신거부 (P0)

- 하나씩 끄기는 사이트에서만: 메일 `알림 설정 관리` → 로그인 → 내 알림(B2-05) 또는 알림 버튼 메뉴(B2-04). 메일에는 개별 해지 링크가 없다(해지하려는 유저도 한 번 더 방문하게 함).
- 모두 끄기: 메일 `전체 수신거부`, 메일 앱 원클릭 수신거부. 로그인 없이 즉시 반영되고 그날 예정분까지 멈춘다.
- 전체 수신거부는 설정해둔 알림을 지우지 않고 전체 알림 끔(일시정지)으로 저장한다. 스팸 신고도 전체 수신거부로 처리하며, 다시 받으려면 유저가 직접 켠다.
- 해지 확인 화면(B2-09): `모든 알림 메일을 껐어요`, `설정해둔 알림 n건과 가입 상품 정보는 그대로 남아요`, [Y-Fin.에서 받을 알림 설정하기], [모두 다시 받기]. 안내 문구 `받을 알림 설정하기는 로그인 후 내 알림에서 할 수 있어요. 다시 설정하면 남은 발송 날짜부터 보내드려요.`
  - [Y-Fin.에서 받을 알림 설정하기]: 로그인 후 내 알림을 열고, 전체 알림 토글을 켠 뒤 원하지 않는 알림만 끄게 한다.
  - [모두 다시 받기]: 끄기 전 설정 그대로 남은 발송 날짜부터 보낸다.
- 로그인 없는 전체 수신거부는 대량 발송 요건이고, 끄는 길이 막히면 스팸 신고로 이어지기 때문이다.

### 6. 마이페이지 내 알림 (P0)

- 마이페이지 탭: `찜해둔 Fin.`, `내 알림`, `개인정보`. 내 가입 상품은 찜해둔 Fin.으로 옮긴다.

| 순서 | 영역 | 내용 | 동작 |
| --- | --- | --- | --- |
| 1 | 안내 배너 | 유형별 자동 발송 시점 안내 | |
| 2 | 알림 받는 곳 | 이메일, 인증 상태, [변경] / 웹 푸시·카카오 알림톡 `준비 중` / 전체 알림 토글 | 토글을 끄면 확인 후 모든 알림 일시정지. 메일 전체 수신거부 상태도 꺼진 상태로 표시 |
| 3 | 다가오는 알림 | 발송 예정 최대 10건 (날짜, 유형, 상품명, `09:00 발송 예정`) | 보기 전용 |
| 4 | 설정해둔 알림 | 필터 `전체 n`, `마감 임박 n` / 카드(유형, D-day, 상품명, 기간, 자동 알림 일정) | [상세 보기](2계층은 [온통청년 보기]), 알림 버튼 `알림 받는 중` |

- 끈 카드는 새로고침 전까지 `알림 받기` 상태로 남아 다시 켤 수 있다.
- 일시정지 중 지난 알림은 다시 켜도 보내지 않는다.
- 문구: 안내 배너 `마감 일정은 7일 · 3일 · 1일 전, 시작 일정은 전날과 당일, 만기는 30일 · 7일 전 오전 9시에 이메일로 알려드려요. 메일 하단 링크로 언제든 끌 수 있어요.` / 다가오는 알림 하단 `같은 날 알림은 한 통으로 묶어 보내드려요`
- 빈 상태·예외: 설정해둔 알림 0건 `아직 설정해둔 알림이 없어요` + [캘린더에서 일정 보기] / 메일 반송 시 상단 `메일이 전달되지 않았어요`(캘린더 상단에도 표시) + [이메일 다시 인증] / 인증 메일 미수신 [인증 메일 다시 받기](1분에 1번)

### 7. 찜해둔 Fin. 카드·가입 등록·만기 알림 (P0)

찜해둔 Fin. 카드: Y3-2 추천 결과 카드 UI를 그대로 쓰고 하단 버튼만 바뀐다.

| 상품·상태 | 왼쪽 | 오른쪽 | 동작 |
| --- | --- | --- | --- |
| 정책상품, 모집 전·예정·모집 중 (설정 전) | [상세 보기] | [알림 받기] | 모집 중이면 마감, 전·예정이면 시작 알림 |
| 정책상품, 알림 설정함 | [상세 보기] | `알림 받는 중` | 작은 메뉴: 보낼 날짜, [알림 끄기] |
| 정책상품, 다음 회차 미정·상시 | [상세 보기] (전체 폭) | 없음 | 회차가 등록되면 [알림 받기] 등장 |
| 은행 상품, 가입 등록 전 | [상세 보기] | [가입했어요] | B2-06 가입 등록 모달 |
| 은행 상품, 가입 등록 후 | [상세 보기] | `가입함 · 만기 D-n` | B2-06 수정 모드 |
| 내 가입 상품 행 | [만기 수익률 계산하기] | [다음 가입 상품 추천받기] | 계산 모달 / 이전 입력값이 채워진 Y3-2 |

- 카드에 신청 페이지로 가는 버튼은 두지 않는다.
- 찜을 해제해도 설정해둔 알림과 내 가입 상품·만기 알림은 유지된다(찜과 알림 설정은 독립).
- 모집 전·예정인데 시작 알림 시점이 모두 지났으면 마감 알림 대체 규칙을 따른다.

내 가입 상품 (찜해둔 Fin. 페이지, 찜 카드 아래)

| 항목 | 규칙 |
| --- | --- |
| 구성 | 제목 `내 가입 상품 n` + [+ 가입 상품 등록], 카드(상품명, 가입일, 기간, 만기 예정일, D-day) |
| 버튼 | [만기 수익률 계산하기], [다음 가입 상품 추천받기]. 두 CTA는 마이페이지 찜해둔 Fin.에만 |
| 만기 알림 | 가입 등록 때 자동 설정. 끄기는 내 알림 탭, 캘린더 만기 일정의 알림 버튼에서 |
| 강조 | 만기 30일 이내 행은 테두리·D-day 강조 |
| 수정·삭제 | 행 클릭 또는 찜 카드 `가입함 · 만기 D-n` → 가입 등록 모달 수정 모드 |
| 빈 상태 | `가입한 상품을 등록하면 만기 전에 알려드려요` + [+ 가입 상품 등록] |

가입 등록 모달 (B2-06)

| 순서 | 영역 | 규칙 |
| --- | --- | --- |
| 1 | 제목·설명 | `가입한 상품 등록` / `가입일을 알려주시면 만기 전에 미리 알려드릴게요` |
| 2 | 상품 | 찜 카드 [가입했어요]로 들어오면 고정. [+ 가입 상품 등록]이면 찜 목록에서 선택 |
| 3 | 가입일 | 오늘이 기본. 미래 날짜, 5년보다 이전 날짜 불가 |
| 4 | 저축 기간 | 1·3·6·12·24·36개월. 상품 기간으로 미리 채우고 `상품 기간으로 미리 채웠어요` 표시 |
| 5 | 만기 예정일 | 입력이 바뀔 때마다 즉시 계산해 날짜와 D-day 표시 |
| 6 | 이렇게 알려드려요 | 만기 30일·7일 전 발송 날짜. 지난 날짜는 `이미 지나서 건너뛰어요` |
| 7 | 버튼 | [등록하고 만기 알림 받기] → 찜 카드 `가입함 · 만기 D-n`, 토스트 |

- 이메일 인증 전 유저는 B2-01의 이메일·동의 고지가 함께 나오고 버튼은 [동의하고 등록하기].

만기 계산 규칙

| 규칙 | 예시 |
| --- | --- |
| 만기 = 가입일 + 저축 기간(개월) | 2025.10.22 + 12개월 = 2026.10.22 |
| 같은 날짜가 없으면 그 달 말일 | 2026.01.31 + 1개월 = 2026.02.28 |
| 휴일은 보정하지 않음 | 화면·메일에 `실제 지급일은 은행 영업일 규칙을 따라요` |
| 만기일이 지나면 | 카드에 `만기됨`, [삭제], [다시 등록] |

- 등록한 상품이 판매 종료돼도 만기 알림은 유지한다.

만기 수익률 계산 모달 (화면 하단)

| 순서 | 영역 | 규칙 |
| --- | --- | --- |
| 1 | 제목·상품 | `만기 수익률 계산`, 상품명, 기간, 만기일 |
| 2 | 예치 금액 (적금은 월 납입액) | 처음에는 Y3-1 월 납입 희망액으로 채우고, 입력하면 저장해 다음에 채움 |

| 4 | 결과 | 원금, 세전 이자, 세후 이자(일반과세 15.4%), 만기 예상 수령액, 세후 수익률 |

- 정부 기여금 상품은 기여금을 포함한 예상 수령액으로 계산한다(Y3-2·Y4 수익 계산 로직 재사용).
- 만기 30일·7일 전 메일의 [만기 후 선택지 비교하기]는 이전 입력값이 채워진 추천 결과로 이동한다 (P1).

### 9. 일정 변경 반영 (P1)

| 변경 | 아직 안 보낸 알림 | 이미 보낸 알림이 있으면 |
| --- | --- | --- |

## 데이터·API

메일 발송 도구, 스케줄러, API 이름과 형식은 개발에서 확정한다.

### BE

- 저장 대상
  - 알림 설정 (대상, 유형, 상태)
  - 전체 알림 상태 (켜짐 / 일시정지, 끈 경로: 마이페이지 / 메일 전체 수신거부 / 스팸 신고)
  - 발송 예정, 발송 이력
  - 가입 등록 (상품, 가입일, 기간, 만기일, 예치 금액)
  - 이메일 인증
  - 수신 동의 이력 (마케팅 동의와 분리)
- 발송 시점 계산: 유형별 시점(마감 7·3·1일 전, 시작 전날·당일, 만기 30·7일 전)을 코드 수정 없이 바꿀 수 있는 설정값으로 관리. 설정 시점 기준 지난 시점은 제외하고, 남은 시점이 없으면 설정 거부.
- 발송 스케줄러: B1 일정 동기화 완료 → 당일 발송분 생성 → 유저별 다이제스트 묶음 → 오전 9시 발송. 중복 발송 방지, 실패 재시도.
- 메일 템플릿 8종(마감, 시작, 만기, 다이제스트, 정정, 인증 등). 본문에 금리·추천 문구가 들어가지 않도록 템플릿 단에서 차단.
- 이메일 인증: 토큰 24시간 유효, 7일 미인증 알림 설정 자동 취소, 재발송 1분에 1번.
- 수신거부: 로그인 없이 쓰는 서명된 전체 수신거부 링크, 메일 앱 원클릭 수신거부(`List-Unsubscribe`) 지원. 전체 수신거부는 전체 알림 일시정지로 저장. 반송·스팸 신고 시 발송 중단. 발신 도메인 인증 등 대량 발송 요건 충족.
- 일정 변경 반영: B1 일정 변경 이벤트 수신 → 남은 발송 예정 재계산 → 이미 보낸 알림이 있으면 정정 메일 1회(같은 회차 하루 1번).
- 조회 API: 설정해둔 알림, 전체 알림 상태, 다가오는 알림, 발송 날짜 미리보기, 리마인드 배너 대상, 내 가입 상품, 찜 상품별 회차 상태·알림 설정·가입 여부.
- 만기 수익률 계산: 가입 상품, 예치 금액(월 납입액), 적용 금리로 만기 예상 수령액과 세후 수익률 계산. Y3-2·Y4 수익 계산 로직 재사용, 입력한 예치 금액은 저장해 다음에 채움.
- 한도·파기: 받는 중 알림 1인 30건. 찜 해제와 알림 설정은 독립. 회원 탈퇴 시 알림 설정, 가입 등록, 발송 이력, 동의 이력 즉시 파기.
- 채널 확장 대비: 웹 푸시·알림톡을 채널만 추가하면 같은 알림 설정으로 보낼 수 있는 구조.

### FE

- 알림 버튼 공통 컴포넌트: 로그인, 인증 상태, 알림 설정 여부, 남은 시점으로 상태 결정. 설정할 수 없는 일정은 숨기고 오늘 마감·30건 한도는 비활성. 리스트·모바일은 아이콘 3단계.
- 알림 설정 분기: 비로그인 → 누르려던 설정을 저장하고 로그인 유도 → 로그인 후 재실행 / 인증 전 → 알림 받기 모달 / 인증 완료 → 원클릭 + 토스트 실행 취소.
- 발송 날짜 미리보기: 모달, 토스트, 가입 등록 모달에서 서버가 계산한 발송 날짜 표시. 가입 등록은 입력이 바뀔 때마다 만기일·D-day 재계산.
- 리마인드 배너: GNB 아래 전역 노출(로그인·약관·정보 입력 단계 제외), 닫기 상태는 그날만 유지.
- 내 알림 탭: 다가오는 알림 최대 10건, 설정해둔 알림 `전체`·`마감 임박` 필터. 전체 알림 토글은 확인 후 일시정지.
- 찜해둔 Fin. 카드: 상품 종류, 회차 상태, 알림 설정 여부, 가입 등록 여부로 하단 버튼 결정. 찜 카드 아래 내 가입 상품 목록, 만기 수익률 계산 모달.
- 메일 링크 화면: B2-08, B2-09는 로그인 없이 열리는 단독 화면. `알림 설정 관리`와 [Y-Fin.에서 받을 알림 설정하기]는 로그인 후 내 알림으로 이동.

## 지표

- 북극성: 알림 경유 재방문율 = 알림 메일·리마인드 배너를 눌러 30일 내 재방문한 유저 / 알림 수신 유저 (목표안 25%)
- KPI
  - 알림 설정 유저 비율: 로그인 유저 중 설정해둔 알림 1건 이상 (목표안 30%)
  - 이메일 오픈율·클릭률 (목표안 40%·10%. 금융업 평균 오픈율 25~27%에 유저가 직접 신청한 메일임을 가산)
  - 알림 받기 모달 완료율, 알림 경유 상세 확인 후 신청 페이지 전환율 (출시 후 기준 설정)
- 보조: 인증 완료율, 찜 직후 제안 수락률, 가입 등록 수, 수신거부율 0.5% 미만, 스팸 신고율 0.1% 미만. 수신거부율이 높으면 자동 발송 시점 수를 줄이는 방향으로 조정.

## 열린 이슈

- 출시 알림 범위 충돌: 「서비스 기획 피봇팅」은 B2를 "알림(만기·마감·출시)"과 "coming soon 구독 채널"로 정의했으나, B2 PRD는 알림을 설정하지 않은 신상품 안내를 광고성으로 보고 제외하고 coming soon 구독은 언급하지 않는다. 이 문서는 B2 PRD를 따르며, coming soon 구독 채널 포함 여부 확인 필요.
- 채널: 피봇팅 문서는 이메일, 웹 알림, 알림톡(건당 평균 10원)을 나열했으나 B2 PRD는 이메일만 출시 범위로 둔다. B2 PRD를 따른다.
- 설정 불가 조건: PRD는 "남은 발송 시점이 없거나(오늘 마감)"라고 했지만 명세의 늦은 설정 표는 "마감 1일 전 오전 9시 이후"도 설정 불가(`내일 마감이에요`)로 본다. 버튼 상태표에는 `내일 마감이에요` 문구가 없어 정리 필요.
- 인증 대기 메뉴: PRD는 인증 안내와 [인증 메일 다시 받기]만, 명세는 [이메일 변경]을 추가했다. 명세를 따랐다.
