# 기획과 구현 차이

> 기준: `main` 브랜치 코드(#35까지)와 노션 기획 문서(2026-10 export). 열려 있는 draft PR #36·#37은 반영하지 않았다. 차이를 발견하면 이 문서에 추가하고, 해소되면 지운다.

"의도된 결정"은 구현하면서 정한 규칙이라 기획 문서 쪽을 고쳐야 하는 항목이고, "확인 필요"는 어느 쪽이 맞는지 팀이 정해야 하는 항목이다.

## 추천 (Y3)

| 항목 | 기획 | 구현 | 구분 |
| --- | --- | --- | --- |
| 정부 상품 `#최고이율_중심` | 지원 내용 금리를 파싱해 상위 30% 매칭 | 정부 상품의 적용 가능 혜택에서 제외 (`GOV_APPLICABLE_BENEFITS`). 정부 상품은 금리 대부분이 미공시라 매칭할 수 없음 | 의도된 결정 |
| 은행 `#최고이율_중심` 상위 30% 모집단 | `intr_rate2` 상위 30% (모집단 불명확) | 이번 요청에서 자격 필터를 통과한 은행 옵션의 `max_rate` 기준 | 의도된 결정 |
| 연령 우대 자동 매칭 | 사용자 생년월일이 만 19~34세면 매칭 | 사용자 나이와 무관하게, 상품의 연령 우대 구간이 19~34세와 겹치면 매칭 (커밋 cd0d31e) | 의도된 결정 |
| 지역 필터 | 온통청년 `zipCd`로 해당 지역 정책만 조회 | 수집된 `REGION_*` 키워드로 사후 필터. 지역 키워드가 없는 정부 상품은 전국으로 간주 | 의도된 결정 |
| 현재 신분 자격 | `jobCd`, `addAplyQlfcCndCn`, `join_member` 텍스트 매칭 | 수집기가 LLM으로 추출한 `REQUIRE`/`EXCLUDE` 조건 중 신뢰도 `HIGH`만 사용 | 의도된 결정 |
| 공제부금형(그룹 2) 제외 | 추천 범위 제외, 상세 진입 차단 | 시드에 넣지 않는 방식으로 제외. 코드에 별도 차단 로직은 없음 | 의도된 결정 |
| 1단계 은행 우대 조건 | 비로그인은 선택, 로그인은 필수 | 로그인 여부와 관계없이 필수 (`BANK_CONDITION_REQUIRED`) | 확인 필요 |
| "총 OO개 중 XX개 제외" | 리스트 상단에 표시 | 응답에 `eligibleProductCount`(통과 수)만 있고 전체 상품 수는 없음 | 확인 필요 |
| 파킹 카드 컬럼 (V8) | 파킹 카드에 최고금리 적용 범위, 이자지급방식 표시 | 컬럼은 있으나 엔티티에 매핑되지 않음. PR #37에서 매핑 | 진행 중 |
| 병역 연령 상한 확장 | 26-06-24에 규칙 삭제 | `allows_military_age_extension`, `military_max_age` 컬럼은 남아 있으나 쓰지 않음 | 정리 대상 |
| 정부 상품 탭 A 은행 거래 배점 | v2.4에서 삭제 (0점) | `GOV_BANK_COND` 가중치 0, 항상 비활성. 명세 A-3 예시에는 삭제 전 "은행 거래 8점"이 남아 있음 | 기획 문서 정리 대상 |

## 상세·계산기·찜 (Y4, Y5)

| 항목 | 기획 | 구현 | 구분 |
| --- | --- | --- | --- |
| 아웃링크 URL 해소 | 상품 코드 단위 매핑 테이블(`terms_url`, `last_checked`, `is_valid`) + 은행 대표 URL 폴백 + `resolution_level` 반환 | 옵션 `apply_url` → 금융기관 `apply_url`(공식 채널) → 없음. 매핑 테이블, 유효성 점검, `resolution_level` 없음 | 확인 필요 |
| 마감 상품 CTA | 정부 `recruit_closed`, 은행 `sale_ended` 구분 | `is_joinable = false`면 모두 `RECRUIT_CLOSED`, 링크 없음 | 확인 필요 |
| 찜 단위 | 상품 코드 (+ 은행은 저축 기간) | 옵션 ID (`product_property_id`). 옵션이 기간·유형별로 나뉘므로 의도는 같음 | 의도된 결정 |
| 찜 목록 API | `GET /me/favorites` | 입력 기반 재계산은 `POST /favorites/list` (요청 본문에 추천 입력), 기본 조회는 `GET /favorites` | 의도된 결정 |
| 찜 목록 지표 잠금 | 상세와 같은 개인화 기준 | 거래 이력 반영 여부만 개인화 판정을 따르고, 지표는 요청 입력이 있으면 계산 | 확인 필요 |
| 계산기 저축 기간 검증 | 상품 `save_trm` 옵션 중 선택 | 요청 DTO 주석에는 옵션 검증이라고 되어 있으나 서비스는 금리 상한과 금액 상한만 검증 | 확인 필요 |

## 루트 README와 코드 불일치

루트 [README](../../README.md)의 API 설명 중 코드와 다른 부분이다. README를 고칠 때 참고한다.

- 추천 응답 필드 이름: README는 `productDetails`, 코드는 `productCardSummaries`(`ProductSearchResultDto`).
- `/term`: README는 `GET /`, `POST /agree`, 코드는 `GET /term`, `POST /term`.
- README 표에 없는 엔드포인트: `GET·PUT·DELETE /user/me/profile`, `GET /providers/banks`, `POST /search/products/{id}/detail`(본문에 설명만 있음).
